# 漏洞分析: wndrmacv1-1.0.0.20 / id:000032,sig:11,src:000292,time:11575317,execs:67647,op:splice,rep:16

## 摘要

- 判定: `确认漏洞`
- Sink位置: `/usr/sbin/uhttpd` `0x43bb2c` `0x43bc90/0x43bc98`（将 `cgi_setobject("rm_access")` 的返回值直接作为 `strcmp` 类函数实参）
- Source位置: `/usr/sbin/uhttpd` `0x43bb2c` `0x43bc6c`（读取 `rm_access`）；控制流source在 `/usr/sbin/uhttpd` `0x40e058` `0x40e0a8`
- 漏洞二进制: `/usr/sbin/uhttpd`
- 漏洞类型: 空指针解引用
- 一句话根因: remote 配置处理函数在 `submit_flag` 命中后会读取 `rm_access`，但未检查返回值是否为 `NULL`，随后直接传给字符串比较函数，导致 `NULL` 解引用崩溃。
- 数据包字段 -> 变量赋值:
  - `body.submit_flag` (`remote&&wzq`) -> `s1`（`0x40e0c0` 保存的 submit_flag 值，用于后续 handler 分发）
  - `body.rm_access` 缺失 -> `v0/s0 == NULL`（`0x43bc80` 返回后在 `0x43bc88/0x43bc8c` 作为比较参数使用）
- 执行顺序:
  1. `uhttpd` 在 `0x40e0a8` 读取 `submit_flag`，trace 随后进入分发表匹配逻辑 `0x40e130 -> 0x40e140 -> 0x40e0f0`。
  2. 命中的 handler 落在 `0x43bb2c`，该函数依次读取 `http_rmport`、`http_rmenable`、`rm_access`。
  3. `rm_access` 缺失导致 `cgi_setobject("rm_access")` 返回 `NULL`，`0x43bc90/0x43bc98` 直接把该 `NULL` 传给字符串比较函数，最终触发 `SIGSEGV`。

  - `0x43bc84`: `rm_access` 查询返回后，trace 在此后立即崩溃

## 数据流细节

- 哪些数据包字段控制了哪些变量:
  - `body.submit_flag` 控制是否进入 `0x43bb2c` 对应的 remote 配置处理路径。
  - `body.rm_access` 本应提供 remote 访问模式；本次请求中该字段缺失，因此读取结果为 `NULL`。
  - `body.endis_wl_radio`、`body.endis_wla_radio`、`body.%20timestamp` 在当前崩溃链中没有看到流入 sink 的证据。
- 哪个函数读取了source字段:
  - `0x40e0a8` 通过常量字符串 `submit_flag` 读取分发字段。
  - `0x43bc6c` 通过常量字符串 `rm_access` 读取会流向 sink 的字段。
- 哪个函数写入 / 拼接 / 格式化了攻击者可控数据:
  - 未观察到复杂拼接；危险值是 `cgi_setobject("rm_access")` 的直接返回值。这里攻击者控制的不是字符串内容，而是“是否提供该字段”，从而让返回值变成 `NULL`。
- 最终如何到达sink:
  - `submit_flag` 命中 remote handler 后，`0x43bc6c` 读取 `rm_access`。
  - 返回值 `v0` 在 `0x43bc88`/`0x43bc8c` 被放入 `a0`/`s0`。
  - `0x43bc94` 装载字符串比较函数，`0x43bc98` 发起调用，对 `NULL` 与常量字符串 `ip_single` 比较，导致崩溃。

## 误报检查

- 为什么这是一个真实漏洞，或者为什么它更像误报:
  - 崩溃信号明确，`container.console.log` 报 `SIGSEGV`，`entry_trace.txt` 末尾显示 `si_addr=NULL`。
  - 崩溃前最后一个本地基本块是 `0x43bc84`，紧邻 `cgi_setobject("rm_access")` 返回点，随后代码无判空即调用字符串比较函数，控制流和数据流都闭合。
  - 数据包中确实缺少 `rm_access` 字段，而 handler 中却强制读取并使用该字段。
- 当前缺失的证据:
  - `0x40dfd8` 对 `submit_flag` 的辅助处理逻辑未完全命名；只能从 trace 证明它参与了分发前处理，不能精确命名其语义。
- 对当前现象的替代解释:
  - 最合理的替代解释是 submit_flag 在内部被规整后才命中 remote handler；但这不会改变核心结论，因为真正导致崩溃的是 `rm_access` 缺失后未判空即比较。

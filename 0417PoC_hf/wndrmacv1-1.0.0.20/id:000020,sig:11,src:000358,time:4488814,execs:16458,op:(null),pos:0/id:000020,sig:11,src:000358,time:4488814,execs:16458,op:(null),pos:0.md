# 漏洞分析: wndrmacv1-1.0.0.20 / id:000020,sig:11,src:000358,time:4488814,execs:16458,op:(null),pos:0

## 摘要

- 判定: `确认漏洞`
- Sink位置: `/usr/sbin/uhttpd 0x00439b00(sym.config_block_sites) 0x00439b58(jalr strcmp)`
- Source位置: `/usr/sbin/uhttpd 0x0040e058(sym.cgi_setobject) 0x0040e0b8(jalr cgi_value("submit_flag", ...))`
- 漏洞二进制: `/usr/sbin/uhttpd`
- 漏洞类型: `NULL pointer dereference`
- 一句话根因: `submit_flag=block_sites` 会把请求分派到 `config_block_sites`，该函数调用 `cgi_value("skeyword", ...)` 取配置项后未检查返回值是否为 `NULL`，随即把 `NULL` 作为 `strcmp` 实参使用并崩溃。
- 数据包字段 -> 变量赋值:
  - `body.submit_flag = "block_sites"` -> `sym.cgi_setobject` 中 `s1 = cgi_value("submit_flag", ...)`，随后与函数表项 `block_sites` 比较并命中 `0x00439b00`
  - `body` 中缺少 `skeyword` -> `sym.config_block_sites` 中 `s0 = v0 = cgi_value("skeyword", ...) = NULL`
  - `body.ap_mode = ";`wzq`"` -> `sym.cgi_setobject` 中 `config_get("ap_mode")` 返回值进入 `strcmp(...,"bpa")` 的参数，仅用于刷新时间分支，不是崩溃根因
- 执行顺序:
  1. `sym.post_apply(0x0040997c)` 解析 POST body，构造键值对数组后调用 `sym.cgi_setobject(0x00409cd4)`
  2. `sym.cgi_setobject(0x0040e0b8)` 读取 `submit_flag`，在函数表 `0x100004b0` 命中字符串 `block_sites(0x004478d0)` 并跳到 `sym.config_block_sites(0x00439b00)`
  3. `sym.config_block_sites(0x00439b3c)` 读取缺失字段 `skeyword`，返回 `NULL` 后在 `0x00439b58` 调用 `strcmp(NULL, "perschedule")`，trace 于 `0x00439b44` 后 SIGSEGV

## 数据流细节

- 哪些数据包字段控制了哪些变量:
  - `body.submit_flag` 控制 `sym.cgi_setobject` 的分派目标，决定进入 `config_block_sites`
  - `body` 中缺失 `skeyword` 控制 `sym.config_block_sites` 中 `cgi_value("skeyword", ...)` 的返回值为 `NULL`
  - `body.ap_mode` 仅影响 `sym.cgi_setobject` 后段 `ap_mode`/刷新时间逻辑，不影响本次崩溃触发
- 哪个函数读取了source字段:
  - `sym.cgi_setobject(0x0040e0b8)` 读取 `submit_flag`
  - `sym.config_block_sites(0x00439b3c)` 读取 `skeyword`
- 哪个函数写入 / 拼接 / 格式化了攻击者可控数据:
  - `sym.post_apply(0x0040997c)` 从 POST body 中拆分 `key=value` 对并写入栈上的键值对数组
  - `sym.cgi_value(0x0040cf10)` 在该键值对数组中按 key 查找并返回 value 指针
- 最终如何到达sink:
  - `post_apply` 解析 `submit_flag=block_sites`
  - `cgi_setobject` 调用 `cgi_value("submit_flag", ...)`，得到指向 `"block_sites"` 的指针
  - `cgi_setobject` 遍历函数表；在 `0x100004b0` 处表项为 `0x004478d0("block_sites"), 4, 0x00439b00`
  - 命中后跳转到 `sym.config_block_sites`
  - `config_block_sites` 调用 `cgi_value("skeyword", ...)`，由于请求里没有该字段而返回 `NULL`
  - 返回值直接进入 `strcmp`，形成 `NULL` 解引用并导致 SIGSEGV

## 误报检查

- 为什么这是一个真实漏洞，或者为什么它更像误报:
  - 这是可复现的真实漏洞。控制流、函数表映射、崩溃地址和危险实参都能对应到同一条链路；不是单纯日志异常，也不是子进程退出噪声。
- 当前缺失的证据:
  - 没有寄存器转储，无法直接打印 `a0/a1` 的运行时值；但从 trace 顺序和反汇编看，`v0` 来自 `cgi_value("skeyword", ...)`，且唯一合理的异常地址是 `strcmp` 对 `NULL` 字符串解引用。
- 对当前现象的替代解释:
  - 最合理的替代解释是 `cgi_value` 内部返回了悬空指针而非 `NULL`。但 console 明确给出 `si_addr=NULL`，且 trace 在 `cgi_value` 返回后立刻进入 `strcmp`，因此该替代解释不成立。

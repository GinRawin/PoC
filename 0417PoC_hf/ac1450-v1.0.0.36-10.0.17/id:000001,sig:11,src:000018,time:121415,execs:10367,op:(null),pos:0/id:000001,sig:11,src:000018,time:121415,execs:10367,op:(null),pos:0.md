Netgear AC1450-1.0.0.36 是 Netgear 旗下的一款路由器固件，受影响固件名称为 AC1450，受影响版本为 1.0.0.36。

AC1450_V1.0.0.36_10.0.17
漏洞名称：Netgear AC1450 pppoe2_domain.cgi 栈缓冲区溢出漏洞
Netgear AC1450-1.0.0.36 的 httpd 二进制文件中存在一个栈缓冲区溢出漏洞，会导致远程攻击者通过构造恶意请求覆写返回地址，使目标进程崩溃，并具备进一步控制执行流的风险。

该漏洞位于二进制文件 usr/sbin/httpd 中，处理路由 `/pppoe2_domain.cgi` 的函数在地址 0x1e428 处调用参数读取函数 0x1654c 读取 `policyIndex`，并把输出缓冲区错误地设置为当前栈帧中的 `sp+0x800`。随后 0x1654c 在 0x16604、0x16618 和 0x16640 处持续向该位置写入用户可控数据，最终越界覆写保存的寄存器和返回地址。

攻击者可以远程发起攻击，通过向 `/pppoe2_domain.cgi` 发送构造的恶意 POST 数据触发漏洞。当前样本请求中的 `policyIndex` 为超长可控字符串，其中偏移 28 到 31 字节处的数据会落到保存的返回地址位置；在本次样本里该位置被 `'aaaa'` 覆写，因此崩溃时表现为 `si_addr=0x61616160`。

漏洞研究环境：

通过模拟仿真进行验证。当前附件中的环境是已经 patch 了认证环节之后的，未 patch 的环境可以用 binwalk 解压对应下载链接的固件得到。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/Netgear/ac1450/ac1450rehost.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 docker-compose build, docker-compose up。

我还附上了复现请求文件，直接重放当前目录下的 packet_1.request.raw 即可。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。攻击者发送一个恶意数据包，请求路由为 `/pppoe2_domain.cgi`。该请求携带空的 `domain` 字段和超长的 `policyIndex` 字段，处理函数在地址 0x1e418 先读取 `domain` 到栈底缓冲区，又在地址 0x1e428 读取 `policyIndex` 到 `sp+0x800`，后者距离保存的返回地址仅剩 28 字节安全空间。
![alt text](image.png)

第二步。参数读取函数 0x1654c 命中 `policyIndex` 后，会在地址 0x16604、0x16618 和 0x16640 处循环执行写入与 URL 解码逻辑，但它只按最多 0x7ff 字节处理输入，并不知道调用方传入的实际目标空间只有很小一段栈尾区域。结果是用户可控数据越过局部变量区，依次覆写保存的 `r4`、`r5`、`r6`、`r7` 和 `pc`。
![alt text](image-1.png)

第三步。函数从 0x1e468 附近准备返回时，被覆写后的返回地址被取出执行。由于当前样本在对应偏移放入了 `'aaaa'`，ARM 在返回取址时表现为 `si_addr=0x61616160`，最终触发 SIGSEGV，说明该请求已经能够稳定破坏控制流。
![alt text](image-2.png)

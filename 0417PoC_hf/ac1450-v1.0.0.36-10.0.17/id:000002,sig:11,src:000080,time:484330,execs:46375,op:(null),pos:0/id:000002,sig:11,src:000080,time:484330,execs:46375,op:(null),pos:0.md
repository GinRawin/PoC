Netgear AC1450-1.0.0.36 是 Netgear 旗下的一款路由器固件，受影响固件名称为 AC1450，受影响版本为 1.0.0.36。

AC1450_V1.0.0.36_10.0.17
漏洞名称：Netgear AC1450 fwSchedulePPP2.cgi 空指针解引用漏洞
Netgear AC1450-1.0.0.36 的 httpd 二进制文件中存在一个空指针解引用漏洞，会导致远程攻击者通过构造恶意请求使目标设备进程崩溃，造成拒绝服务。

该漏洞位于二进制文件 usr/sbin/httpd 中，处理路由 `/fwSchedulePPP2.cgi` 的函数在地址 0x3a688 处把多个 `schedule_*` 字段格式化为 `pppoe2_schedule_config`，并在地址 0x3a69c 调用函数 0x3a19c 重新解析该配置。函数 0x3a19c 在地址 0x3a218 处对 `strcpy` 的调用缺少判空检查，当第二次 `strtok_r` 返回 NULL 时会直接触发崩溃。

攻击者可以远程发起攻击，通过发送构造的恶意数据包触发漏洞。当前样本请求体为 `{}`，没有提供 `schedule_day`、`schedule_alldayenable`、`starthour`、`startminute`、`endhour`、`endminute` 和 `result` 等字段，处理函数会把这些缺失参数保留为空字符串，并进一步拼接生成异常的 `pppoe2_schedule_config="0::::"`。

漏洞研究环境：

通过模拟仿真进行验证。当前附件中的环境是已经 patch 了认证环节之后的，未 patch 的环境可以用 binwalk 解压对应下载链接的固件得到。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/Netgear/ac1450/ac1450rehost.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 docker-compose build, docker-compose up。

我还附上了复现请求文件，直接重放当前目录下的 packet_1.request.raw 即可。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。攻击者发送一个恶意数据包，请求路由为 `/fwSchedulePPP2.cgi`。该请求体为空对象，因此 `schedule_day`、`schedule_alldayenable`、`starthour`、`startminute`、`endhour`、`endminute` 和 `result` 等参数都无法被 0x1654c 正常读取，对应缓冲区保持为空字符串。
![alt text](image.png)

第二步。处理函数 0x3a508 在地址 0x3a688 调用 `sprintf("%d:%s:%s:%s:%s", ...)`，把上述空字段拼成 `0::::`，随后通过 `acosNvramConfig_set("pppoe2_schedule_config", value)` 和 `acosNvramConfig_save()` 将这一异常配置写入并保存。
![alt text](image-1.png)

第三步。函数 0x3a19c 重新读取 `pppoe2_schedule_config` 后，第一次 `strtok_r` 可以得到 `"0"`，但第二次 `strtok_r(NULL, ":", &saveptr)` 面对连续分隔符时返回 NULL。代码在地址 0x3a218 仍然直接执行 `strcpy(dst, NULL)`，最终触发空指针解引用并导致 SIGSEGV。
![alt text](image-2.png)

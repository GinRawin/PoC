## 误报检查

- 为什么这是一个真实漏洞，或者为什么它更像误报:
  - 这是一个真实漏洞。容器日志和 trace 都显示子进程发生 `SIGSEGV`，且 `si_addr=NULL`。
  - 反汇编能把崩溃路径闭合到具体 sink：`cgi_value("skeyword", ...) -> NULL -> strcmp(NULL, "perschedule")`。
  - `VulPacket.json` 中确实提供了到达该回调所需的 `submit_flag=block_sites`，同时缺失了 `skeyword`，与空指针返回条件完全一致。
- 当前缺失的证据:
  - 无决定性缺口；虽然 trace 没逐条记录进入 libc `strcmp` 内部，但 `0x40ba3c` 所在基本块紧接着把 `a0=v0` 并在 `0x40ba50` 调用 `strcmp`，配合 `si_addr=NULL` 已足够确认。
- 对当前现象的替代解释:
  - 更弱的替代解释是 `parsed_pairs/count` 被破坏导致 `cgi_value` 异常返回空值，但这与前一层 `cgi_setobject` 已成功用同一对象数组读取 `submit_flag` 并命中回调不符，因此不成立。

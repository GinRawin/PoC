漏洞名称：
Netgear WNDR3700v2 1.0.0.8 sprintf 栈缓冲区溢出漏洞

Netgear WNDR3700v2 1.0.0.8 是 Netgear 公司旗下的一款网络设备固件，受影响产品为 WNDR3700v2，受影响版本为 1.0.0.8。

Netgear WNDR3700v2 1.0.0.8 的 `/usr/sbin/uhttpd` 二进制文件中存在一个 `栈缓冲区溢出` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。uhttpd 将请求体 select_approved_item 原样作为 %s 传入 sprintf(sp+0x18, "/sbin/hotplug2.testbusy USB_approved_device%s", attacker)，目标栈缓冲区仅 0x80 字节，导致返回地址区域被覆盖，并在函数返回时跳到 0x61616160 崩溃。

该漏洞位于二进制文件 `/usr/sbin/uhttpd` 中。程序在 `/usr/sbin/uhttpd 0x4158e4` 处对攻击者可控输入完成读取、解析或传递，并最终在 `/usr/sbin/uhttpd 0x4234c0` 处进入危险操作，最终导致栈破坏并触发进程崩溃。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前样本目录中提供了对应的请求包与发送脚本 send.py，可用于复现该问题。

原始固件可通过上述官方链接获取。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0417PoC_hf/wndr3700v2-1.0.0.8/wndr3700v2-1.0.0.8.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。POST /apply.cgi? 携带 submit_flag=usb_approved_del 与超长 select_approved_item 进入 uhttpd

第二步。0x4158fc 以键名 select_approved_item 读取请求字段，并在 0x415914 保存到全局变量

第三步。0x416dd4 取出该全局指针作为参数调用 0x4235d4

第四步。0x4235fc 再调用 0x4234c0(a0=user_ptr)；0x423500 用 sprintf 把攻击者字符串写入 sp+0x18

第五步。长度 43 + 512 = 555 字节的数据覆盖 0x80 字节局部缓冲区及保存的寄存器/返回地址，system() 返回后在函数退出阶段跳转到 0x61616160 并触发 SIGSEGV

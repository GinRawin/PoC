# 漏洞分析: wndrmacv2-1.0.0.4 / id:000013,shmid:11,addr:0x7,4253752

## 摘要

- 判定: `确认漏洞`
- Sink位置: `/usr/sbin/uhttpd sym.cmd_wifi_coexist 0x4124dc`
- Source位置: `/usr/sbin/uhttpd sym.cgi_setobject 0x40e0a8`
- 漏洞二进制: `/usr/sbin/uhttpd`
- 漏洞类型: `NULL pointer dereference`
- 一句话根因: `submit_flag=wifi_channel_coexist` 触发 `cgi_commit()` 调用 `cmd_wifi_coexist()`，但其传入的 2.4G coexist 配置指针为空，`cmd_wifi_coexist` 在 `0x4124dc` 直接读取 `arg[0]`，导致 `SIGSEGV (si_addr=NULL)`。
- 数据包字段 -> 变量赋值:
  - `body.submit_flag=wifi_channel_coexist` -> `cgi_value("submit_flag")` -> `sym.cgi_setobject` 选中 `cgi_action[0xc8]` -> `sym.cgi_commit` 执行 `sym.cmd_wifi_coexist`
  - `body.wl_disablecoext` 缺失 -> `0x10010000-0x2f80` 对应的全局参数槽位保持 `NULL` -> 作为 `a0` 传入 `sym.cmd_wifi_coexist`
  - `body.%20timestamp=pptp` -> 仅用于通过 `check_timestamp` / 请求校验，不是崩溃数据源
- 执行顺序:
  1. `POST /apply.cgi?` 请求进入 `uhttpd` 的 apply 路径，`sym.cgi_setobject` 在 `0x40e0a8` 读取 `submit_flag`。
  2. `submit_flag=wifi_channel_coexist` 使 `cgi_action[0xc8]` 被置位，随后子进程进入 `sym.cgi_commit`。
  3. `sym.cgi_commit` 在 `0x40e838/0x40e840` 取出全局参数槽位 `-0x2f80` 并调用 `sym.cmd_wifi_coexist`；`sym.cmd_wifi_coexist` 在 `0x4124dc` 对空指针做 `lb 0(a0)` 并崩溃。

## 数据流细节

- 哪些数据包字段控制了哪些变量:
  - `body.submit_flag=wifi_channel_coexist` 控制 `sym.cgi_setobject` 选择哪一个 commit 动作，并最终置位 `cgi_action[0xc8]`
  - `body.wl_disablecoext` 是 `sym.cmd_wifi_coexist` 对应的内容字段。该字段在当前包中缺失，导致对应全局参数槽位为空
  - `body.%20timestamp` 只帮助请求通过前置检查
- 哪个函数读取了source字段:
  - `sym.cgi_setobject` 在 `0x40e0a8` 调用 `sym.cgi_value("submit_flag", ...)`
- 哪个函数写入 / 拼接 / 格式化了攻击者可控数据:
  - 当前 crash 不是字符串拼接溢出，而是 `sym.cgi_setobject` / apply 路径把表单字段映射到全局配置槽位；`sym.cgi_commit` 在 `0x40e840` 直接从该槽位取指针给 `sym.cmd_wifi_coexist`
- 最终如何到达sink:
  - `submit_flag` 命中 `wifi_channel_coexist` 分支
  - `sym.cgi_commit` 检查 `cgi_action[0xc8] == 1`
  - `sym.cgi_commit` 用 `lw a0, -0x2f80(v0)` 取出 2.4G coexist 参数指针
  - `sym.cmd_wifi_coexist` 在 `0x4124dc` 直接读取 `*(char *)a0`
  - 由于该指针为 `NULL`，触发 `SIGSEGV`

## 误报检查

- 为什么这是一个真实漏洞，或者为什么它更像误报:
  - 这是一个真实漏洞。崩溃点、调用点和危险实参都可回到真实指令核验：`container.console.log` 报 `SIGSEGV`，trace 显示子进程在 `0x4124d0` 崩溃，反汇编证明 `sym.cgi_commit` 把空指针作为 `a0` 传给 `sym.cmd_wifi_coexist`，而 `sym.cmd_wifi_coexist` 第一条有效访存就是 `lb v0, (a0)`。
- 当前缺失的证据:
  - 不能仅靠当前目录内材料把 `-0x2f80` 这个全局槽位的符号名百分之百恢复出来；`wl_disablecoext` 是结合字符串集合、功能语义和邻接的 `cmd_wifi_coexist_an` / `wla_disablecoext` 做出的高可信推断。
- 对当前现象的替代解释:
  - 最合理替代解释是：该槽位也可能对应 `hidd_coexist_flag` 一类同页面的隐藏字段，而非 `wl_disablecoext` 本身。但这不影响漏洞成立，因为无论具体字段名是哪一个，真实根因都是 `wifi_channel_coexist` 分支下读取了一个未初始化的空指针参数。

漏洞名称：
Tenda AC500 V1 1.0.0.14-EN-TD 0x279d4 空指针解引用漏洞

Tenda AC500 V1 1.0.0.14-EN-TD 是 Tenda 公司旗下的一款网络设备固件，受影响产品为 AC500 V1，受影响版本为 1.0.0.14-EN-TD。

Tenda AC500 V1 1.0.0.14-EN-TD 的 `/bin/httpd` 二进制文件中存在一个 `空指针解引用` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。websAccept 在 POST 请求头解析完后，仅凭 Content-Length > 0 就进入请求体拼接分支；当本轮实际未读到 body 数据时，局部 body 指针保持 NULL，随后对其执行 strlen(NULL) 并崩溃。

该漏洞位于二进制文件 `/bin/httpd` 中。程序在 `/httpd websAccept@0x28694 0x28abc (atoi(Content-Length)) / 0x28ac8 (wp->e0 = Content-Length) 0x28694` 处对攻击者可控输入完成读取、解析或传递，并最终在 `/bin/httpd websAccept@0x279d4 0x27b98 (bl strlen@plt, r0 = [fp-0x24] = NULL) 0x279d4` 处进入危险操作，最终导致进程崩溃并造成拒绝服务。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前样本目录中提供了对应的请求包与发送脚本 send.py，可用于复现该问题。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0417PoC_hf/us-ac500v1br-v1.0.0.14-en-td/us-ac500v1br-v1.0.0.14-en-td.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。20_tb_log.txt 中子进程解析请求头，在 0x28abc/0x28ac8 把 Content-Length 转成 wp->e0 并置位 0x400

第二步。同一轮读取返回 0，27f1c 没有生成新的 body 字符串，但仍在 0x28210 把状态设为 8 并返回

第三步。外层 websAccept 在 0x27b98 对空指针调用 strlen，trace/20_tb_log.txt 与 container.console.log 均显示 SIGSEGV

漏洞名称：
Tenda AC500 websAccept 0x27b98 空指针解引用漏洞

Tenda AC500是Tenda公司旗下的一款路由器固件，受影响固件名称为us-ac500v1br-v1.0.0.14-en-td，受影响版本为V1.0.0.14。

us-ac500v1br-v1.0.0.14-en-td
Tenda AC500的/bin/httpd二进制文件中存在一个空指针解引用漏洞。远程攻击者可以通过发送构造的POST请求触发HTTP请求解析状态机异常，使程序在已经识别出Content-Length且准备进入请求体处理分支时，没有获得新的body字符串却继续沿用空指针变量，随后在websAccept函数内执行strlen(NULL)，最终导致httpd进程崩溃并造成拒绝服务。

该漏洞位于二进制文件/bin/httpd中，关键调用链可概括为websAccept(0x279d4) -> 请求头解析逻辑(0x28694) -> 返回外层状态机 -> websAccept case 8分支(0x27b70/0x27b98)。在处理当前样本对应的POST请求时，请求同时包含/cgi-bin特征和正的Content-Length，程序在请求头阶段把长度字段写入请求结构并置位对应标志位，随后将状态推进到需要拼接请求体的分支。但是该轮执行过程中并没有生成新的body指针，局部变量仍然为NULL，最终在0x27b98附近对该空指针调用strlen并触发SIGSEGV。

攻击者可以远程发起攻击，通过向`/error.asp?1004//cgi-bin/cgi-bin/cgi-bin`发送POST请求触发漏洞。当前样本请求中携带了`Content-Length: 434`和非空请求体，这些字段共同影响了httpd对状态机和请求体处理分支的选择。

漏洞研究环境：

基于当前样本目录中的现有分析材料进行研判。样本目录中包含触发报文`packet_1.request.raw`、发送脚本`send.py`以及已有分析记录，可用于还原触发路径和关键输入特征。根据已有分析结果，本次崩溃点位于`/bin/httpd`的`websAccept`函数内部，属于用户态可复现的空指针解引用问题。

目标配置情况：

未看到需要额外配置的信息，按已有样本材料可视为默认仿真启动后的http服务处理流程。

具体验证过程：

第一步。攻击者发送一个POST请求，请求行为`POST /error.asp?1004//cgi-bin/cgi-bin/cgi-bin HTTP/1.1`，并在头部中携带`Content-Type: application/json`与`Content-Length: 434`，同时附带非空请求体数据。该输入使httpd进入`websAccept`主处理逻辑，并满足后续请求体处理所需的基本条件。
![alt text](image-1.png)

第二步。程序在`websAccept`内部首先解析请求行和请求头。由于URI中包含`cgi-bin`特征，请求对象中的相关标志位被设置；随后在请求头解析过程中识别到`Content-Length`字段，并将其转换后写入请求结构中的长度成员，同时置位表示“存在请求体长度”的状态标志。这一步使状态机认为后续需要继续处理请求体。
![alt text](image-2.png)
![alt text](image-3.png)

第三步。问题出现在请求头解析结束后返回外层状态机的阶段。已有分析表明，辅助处理逻辑会先清空用于返回请求体片段的局部指针，但当前轮并没有为这个指针重新分配或填充有效字符串；尽管如此，程序仍然依据前面设置的标志位把状态推进到对应的case 8分支，并返回成功。
![alt text](image-4.png)
![alt text](image-5.png)

第四步。`websAccept`回到case 8分支之后，继续把该局部变量当作新的请求体字符串使用。由于此时旧的保护条件没有拦住该路径，程序在0x27b70附近进入字符串长度计算逻辑，并在0x27b98处对NULL指针执行`strlen`，最终触发段错误，导致httpd子进程崩溃。
![alt text](image-6.png)
![alt text](image-7.png)

第五步。结合已有样本分析可知，这不是不同样本之间复用出的结论，而是该样本自身请求特征导致的状态推进错误：非空POST body和正的Content-Length让程序认定应当继续处理请求体，但本轮实际没有构造出可用的body字符串，因此在后续分支中形成了空指针解引用。

漏洞名称：
Tenda AC500 websAccept 0x27dd0 空指针解引用漏洞

Tenda AC500是Tenda公司旗下的一款路由器固件，受影响固件名称为us-ac500v1br-v1.0.0.14-en-td，受影响版本为V1.0.0.14。

us-ac500v1br-v1.0.0.14-en-td
Tenda AC500的/bin/httpd二进制文件中存在一个空指针解引用漏洞。远程攻击者可以通过发送构造的POST请求，使程序在已经保存URL查询串的情况下继续进入参数拼接分支，但新的POST数据实际上为空，导致程序对空指针执行strlen，最终引发httpd进程崩溃并造成拒绝服务。

该漏洞位于二进制文件/bin/httpd中，关键调用链可概括为websAccept(0x279d4) -> 请求行解析(0x282a8) -> URL查询串写入req->a4(0x28544) -> 外层状态机推进到case 4 -> websAccept在0x27d70附近拼接参数 -> 0x27dd0调用strlen。当前样本的关键点在于，请求行中已经携带了`?1004`查询串，程序将其保存到`req->a4`，而后续这轮POST正文读取结果为0，辅助函数返回时输出字符串仍为空指针。随后外层逻辑误以为自己拿到了新的参数串，继续与已有查询串进行拼接，在第二次strlen时触发空指针解引用。

攻击者可以远程发起攻击，通过向`/cgi-bin/goform/goform/cgi-bin/goform/goform//error.asp?1004`发送POST请求触发漏洞。当前样本请求头中存在`Content-Length: 0`，同时URL自带查询串`1004`，这两点共同决定了该样本的漏洞触发方式。

漏洞研究环境：

基于当前样本目录中的现有分析材料进行研判。样本目录中包含触发报文`packet_1.request.raw`、发送脚本`send.py`以及已有分析记录。结合已有分析可知，本次崩溃发生在`/bin/httpd`处理POST请求的参数拼接阶段，属于可由远程请求触发的空指针解引用问题。

目标配置情况：

没有看到需要额外启用的特定配置，按已有样本材料可视为默认仿真环境下的http请求处理流程。

具体验证过程：

第一步。攻击者发送POST请求，请求行为`POST /cgi-bin/goform/goform/cgi-bin/goform/goform//error.asp?1004 HTTP/1.1`，头部中带有`Content-Length: 0`和自定义字段`hEaDrE: WZq`。由于URL部分已经带有查询串`?1004`，程序在请求行解析阶段会记录这一参数信息。
![alt text](image-1.png)

第二步。程序进入`websAccept`并解析请求行。已有分析指出，请求行会经过URL拆分和解析，随后把查询串部分写入请求结构中的`req->a4`字段。对于当前样本来说，`req->a4`中保存的是来自`?1004`的参数内容，这为后续进入“已有参数 + 新参数拼接”的分支创造了条件。
![alt text](image-2.png)
![alt text](image-3.png)

第三步。随后程序继续尝试读取POST正文，但由于本次请求的`Content-Length`为0，本轮读取并没有得到新的正文内容。已有分析表明，相关辅助函数在进入时会先将输出参数清零，而当前路径下又没有重新写回有效字符串，只是把状态从前一阶段推进到case 4对应的分支并返回成功。
![alt text](image-4.png)
![alt text](image-5.png)

第四步。外层`websAccept`在进入case 4分支后，认为自己同时拥有已有查询串和新的POST参数，于是开始执行拼接逻辑。程序先对`req->a4`执行长度计算，然后继续对本轮返回的“新参数串”计算长度；然而该指针实际上仍为NULL，因此在0x27dd0附近执行`strlen(NULL)`并触发SIGSEGV。
![alt text](image-6.png)
![alt text](image-7.png)

第五步。当前样本与另一样本的触发原因并不相同。这里的核心不是正的Content-Length配合非空body，而是“URL中已有查询串 + POST正文长度为0 + 状态机仍进入参数拼接分支”这一组合，最终导致httpd对空指针进行字符串处理并崩溃。

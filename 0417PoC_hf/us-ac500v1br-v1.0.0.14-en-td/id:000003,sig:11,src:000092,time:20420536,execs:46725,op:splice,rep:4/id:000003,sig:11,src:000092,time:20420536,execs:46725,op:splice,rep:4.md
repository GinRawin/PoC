漏洞名称：
Tenda AC500 V1 1.0.0.14-EN-TD 0x27dd0 空指针解引用漏洞

Tenda AC500 V1 1.0.0.14-EN-TD 是 Tenda 公司旗下的一款网络设备固件，受影响产品为 AC500 V1，受影响版本为 1.0.0.14-EN-TD。

Tenda AC500 V1 1.0.0.14-EN-TD 的 `/bin/httpd` 二进制文件中存在一个 `空指针解引用` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。websAccept 在 state==2 且本轮读取长度为 0 时把状态推进到 4 并返回成功，但没有给输出字符串赋值；随后 state==4 分支把这个 NULL 指针当成新参数串做 strlen，导致崩溃。

该漏洞位于二进制文件 `/bin/httpd` 中。程序在 `/bin/httpd websAccept 0x282a8 解析请求行，0x28544 将 URL 解析出的查询串写入 req->a4 0x282a8` 处对攻击者可控输入完成读取、解析或传递，并最终在 `/bin/httpd websAccept 0x27dd0 -> strlen@plt(0xd02c)，危险实参来自栈变量 [fp-0x24] 0x27dd0` 处进入危险操作，最终导致进程崩溃并造成拒绝服务。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前样本目录中提供了对应的请求包与发送脚本 send.py，可用于复现该问题。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0417PoC_hf/us-ac500v1br-v1.0.0.14-en-td/us-ac500v1br-v1.0.0.14-en-td.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。0x282a8 解析请求行中的 URL，并在 0x28544 把 ?1004 的查询串保存到 req->a4

第二步。后续一次读取走到 0x281d0/0x281e0/0x2822c/0x28260，因读到 0 字节仅推进状态到 4，但输出字符串仍为 NULL

第三步。0x27d70 分支认为自己拿到了新的参数串，先取 req->a4，再在 0x27dd0 对 NULL 调 strlen，trace/21_tb_log.txt 在 0x27db8 后报 SIGSEGV si_addr=NULL

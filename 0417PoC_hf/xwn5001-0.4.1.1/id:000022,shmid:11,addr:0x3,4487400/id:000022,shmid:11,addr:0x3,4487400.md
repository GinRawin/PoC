漏洞名称：
Netgear XWN5001 0.4.1.1 0x00411f4c 空指针解引用漏洞

Netgear XWN5001 0.4.1.1 是 Netgear 公司旗下的一款网络设备固件，受影响产品为 XWN5001，受影响版本为 0.4.1.1。

Netgear XWN5001 0.4.1.1 的 `/usr/sbin/uhttpd` 二进制文件中存在一个 `空指针解引用` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。submit_flag=wifi_channel_coexist 选中 wifi_channel_coexist 回调并将全局 flag cfg[0xd8] 置 1，但请求里缺少 hidd_coexist_flag，导致 NULL 被写入全局 0x47e12c，后续在 0x411f4c 被当作字符串首字节解引用而崩溃。

该漏洞位于二进制文件 `/usr/sbin/uhttpd` 中。程序在 `uhttpd fcn.0040b5f4 0x0040b68c (调用 fcn.0040b4a4 查找 "hidd_coexist_flag") 0x0040b68c` 处对攻击者可控输入完成读取、解析或传递，并最终在 `uhttpd fcn.00411f48 0x00411f4c 0x00411f4c` 处进入危险操作，最终导致进程崩溃并造成拒绝服务。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前附件中的环境是已经 patch 了认证环节之后的，未 patch 的环境可以通过上述下载链接获取对应固件。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0412PoC/xwn5001-0.4.1.1.zip/xwn5001-0.4.1.1.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。请求体中的 submit_flag=wifi_channel_coexist 被 fcn.0040b95c 读取，并与回调表中的字符串 wifi_channel_coexist 匹配。

第二步。fcn.0040b95c 调用 fcn.0040b5f4 处理 wifi_channel_coexist，同时将表项偏移 0x36 * 4 = 0xd8 置 1。

第三步。fcn.0040b5f4 三次调用 fcn.0040b4a4 查找 hidd_coexist_flag / hidd_wifi_restart_flag，trace 显示三次都走了空值分支，最终把 NULL 写入全局 0x47e12c。

第四步。后续输出函数 fcn.0040c844 发现 cfg[0xd8] == 1，在 0x40ca5c 取出 a0 = *(0x47e12c)，并在 0x40ca58 调用 fcn.00411f48。

第五步。fcn.00411f48 在 0x00411f4c 执行 lb v1, 0(a0)，此时 a0 == NULL，触发 SIGSEGV。

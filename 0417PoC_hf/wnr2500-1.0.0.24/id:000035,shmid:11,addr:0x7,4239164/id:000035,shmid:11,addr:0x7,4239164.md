漏洞名称：
Netgear WNR2500 1.0.0.24 0x40af44 空指针解引用漏洞

Netgear WNR2500 1.0.0.24 是 Netgear 公司旗下的一款网络设备固件，受影响产品为 WNR2500，受影响版本为 1.0.0.24。

Netgear WNR2500 1.0.0.24 的 `/usr/sbin/uhttpd` 二进制文件中存在一个 `空指针解引用` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。submit_flag=wifi_channel_coexist 只负责置位 cgi_action[0xbc]，但对应参数 hidd_coexist_flag 缺失时回调 0x409d40 不会写入全局参数指针 *(0x482158)，cgi_commit 仍无校验地把该 NULL 传给 cmd_wifi_coexist，在 lb v1,(a0) 处崩溃。

该漏洞位于二进制文件 `/usr/sbin/uhttpd` 中。程序在 `/usr/sbin/uhttpd fcn.00409d40 0x409d74` 处对攻击者可控输入完成读取、解析或传递，并最终在 `/usr/sbin/uhttpd sym.cgi_commit 0x40af44` 处进入危险操作，最终导致进程崩溃并造成拒绝服务。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前样本目录中提供了对应的请求包与发送脚本 send.py，可用于复现该问题。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0417PoC_hf/wnr2500-1.0.0.24/wnr2500-1.0.0.24.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。uhttpd 在请求处理中进入 cgi_setobject，用 submit_flag 命中 wifi_channel_coexist 表项 { "wifi_channel_coexist", 0x2f, 0x409d40 }

第二步。cgi_setobject 先把 obj.cgi_action[0xbc] 置 1，再调用回调 0x409d40；该回调读取 hidd_coexist_flag 失败并直接返回，没有给 *(0x482158) 赋值

第三步。子进程 39 进入 cgi_commit，看到 obj.cgi_action[0xbc] == 1 后执行 cmd_wifi_coexist(*(0x482158))，a0=NULL，在 0x40fa98 处触发 SIGSEGV

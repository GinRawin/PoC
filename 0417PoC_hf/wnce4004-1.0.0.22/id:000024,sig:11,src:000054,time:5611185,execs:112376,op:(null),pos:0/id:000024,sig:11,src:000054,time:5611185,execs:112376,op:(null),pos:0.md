漏洞名称：
Netgear WNCE4004 block_sites 处理流程中的空指针解引用漏洞

Netgear WNCE4004 1.0.0.22 是 Netgear 公司旗下的一款无线网桥固件，受影响产品为 WNCE4004，受影响版本为 1.0.0.22。

Netgear WNCE4004 1.0.0.22 的 /usr/sbin/uhttpd 二进制文件中存在一个空指针解引用漏洞。远程攻击者可以构造特定的 POST 请求，通过 submit_flag 命中 block_sites 处理分支，并省略 skeyword 参数，使程序把空指针直接传给 strcmp，最终导致进程崩溃。

该漏洞位于二进制文件 /usr/sbin/uhttpd 中。程序在 cgi_setobject 中读取 submit_flag，并根据其值选择对应 CGI 处理函数。本样本请求体中包含 submit_flag=block_sites，但没有 skeyword 字段。程序在 0x40a91c 处调用 cgi_value("skeyword") 返回 NULL，随后在 0x40a938 处调用 strcmp(a0=NULL, "perschedule")，最终触发 SIGSEGV。

攻击者可以远程发起攻击，通过发送缺少 skeyword 字段的恶意 POST 请求触发该漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前分析基于 greenhouse 仿真环境中的 WNCE4004 1.0.0.22 固件镜像完成。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。当前样本目录中的现有请求、trace 和容器日志已经能够确认 submit_flag 分发、skeyword 缺失及后续 strcmp 空指针崩溃的完整流程。

目标配置情况：

未进行特殊配置，使用默认仿真环境启动即可复现。

具体验证过程：

第一步。攻击者发送 POST 请求访问 /apply.cgi?/wait_for_ca_connect.htm，请求体中包含 submit_flag=block_sites，但没有 skeyword 参数。

第二步。uhttpd 在 cgi_setobject 中读取 submit_flag，并在对象分发表中命中 block_sites 对应的处理函数 0x40a8e0。随后该函数尝试继续读取 skeyword 参数。
![alt text](image.png)

第三步。由于当前请求中缺少 skeyword，cgi_value 返回 NULL。程序没有对返回值进行检查，而是在 0x40a938 处直接把 NULL 作为 strcmp 的第一个参数，最终触发空指针解引用并导致 uhttpd 进程崩溃。

漏洞名称：
Netgear WNCE4004 wlan/change_wps 处理流程中的空指针解引用漏洞

Netgear WNCE4004 1.0.0.22 是 Netgear 公司旗下的一款无线网桥固件，受影响产品为 WNCE4004，受影响版本为 1.0.0.22。

Netgear WNCE4004 1.0.0.22 的 /usr/sbin/uhttpd 二进制文件中存在一个空指针解引用漏洞。远程攻击者可以构造特定的 POST 请求，通过 submit_flag 命中 wlan 对应的 change_wps 处理分支，并省略 hid_dut_type 参数，使程序在后续逻辑中直接解引用空指针，最终导致进程崩溃。

该漏洞位于二进制文件 /usr/sbin/uhttpd 中。程序在 cgi_setobject 中根据 submit_flag 值选择处理函数。本样本请求体中包含 submit_flag=wlan，但没有 hid_dut_type。程序在 change_wps 函数中于 0x40fd9c 处调用 cgi_value("hid_dut_type") 返回 NULL，随后在 0x40fde4 处执行 lb v1, (s0) 直接读取空指针，最终触发 SIGSEGV。

攻击者可以远程发起攻击，通过发送缺少 hid_dut_type 字段的恶意 POST 请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前分析基于 greenhouse 仿真环境中的 WNCE4004 1.0.0.22 固件镜像完成。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。当前样本目录中的原始请求、trace 和容器日志能够对应到 submit_flag 分发表项、change_wps handler 以及 hid_dut_type 缺失后的空指针解引用路径。

目标配置情况：

未进行特殊配置，使用默认仿真环境启动即可复现。

具体验证过程：

第一步。攻击者发送 POST 请求访问 /apply.cgi?/wait_for_ca_connect.htm，请求体中包含 submit_flag=wlan，但没有 hid_dut_type 参数。

第二步。uhttpd 在 cgi_setobject 中读取 submit_flag，并匹配到 wlan 对应的处理函数 change_wps。进入该函数后，程序继续尝试从 CGI 参数表中读取 hid_dut_type。
![alt text](image.png)

第三步。由于当前请求中缺少 hid_dut_type，cgi_value 返回 NULL。程序没有做任何空指针检查，而是在 0x40fde4 处直接读取该指针指向的内容，最终触发空指针解引用并导致 uhttpd 进程崩溃。

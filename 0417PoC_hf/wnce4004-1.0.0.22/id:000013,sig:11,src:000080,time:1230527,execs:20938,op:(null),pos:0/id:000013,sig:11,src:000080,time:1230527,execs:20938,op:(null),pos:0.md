漏洞名称：
Netgear WNCE4004 ca_change_language 处理流程中的空指针解引用漏洞

Netgear WNCE4004 1.0.0.22 是 Netgear 公司旗下的一款无线网桥固件，受影响产品为 WNCE4004，受影响版本为 1.0.0.22。

Netgear WNCE4004 1.0.0.22 的 /usr/sbin/uhttpd 二进制文件中存在一个空指针解引用漏洞。远程攻击者可以构造特定的 POST 请求，通过 submit_flag 命中 ca_change_language 处理分支，并省略 hidden_lang_avi 参数，使程序把空指针直接作为 strcpy 的源参数使用，最终导致进程崩溃。

该漏洞位于二进制文件 /usr/sbin/uhttpd 中。程序在 cgi_setobject 中读取表单参数 submit_flag，并根据其内容选择具体的 CGI 处理函数。本样本请求体包含 submit_flag=ca_change_language，但没有提供 hidden_lang_avi。程序在 0x434a28 处调用 cgi_value("hidden_lang_avi") 返回 NULL，随后在 0x434a60 处执行 strcpy(sp+0x20, s1)，其中 s1 为 NULL，最终触发 SIGSEGV。

攻击者可以远程发起攻击，通过发送缺少 hidden_lang_avi 字段的恶意 POST 请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前分析基于 greenhouse 仿真环境中的 WNCE4004 1.0.0.22 固件镜像完成。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。当前样本目录中的原始请求、trace 和容器日志已经能够确认 submit_flag 分发、cgi_value 返回空值以及后续 strcpy 崩溃的完整链条。

目标配置情况：

未进行特殊配置，使用默认仿真环境启动即可复现。

具体验证过程：

第一步。攻击者发送 POST 请求访问 /apply.cgi?connect_status，请求体中包含 submit_flag=ca_change_language，但不提供 hidden_lang_avi 参数。

第二步。uhttpd 在 cgi_setobject 中读取 submit_flag，并在分发表中匹配到 ca_change_language 对应的处理函数 0x4349b4。随后该函数继续从 CGI 参数中读取 hidden_lang_avi。
![alt text](image.png)

第三步。由于当前请求中缺少 hidden_lang_avi，cgi_value 返回 NULL。程序没有进行空指针检查，仍在 0x434a60 处调用 strcpy(sp+0x20, NULL)，最终触发空指针解引用并导致 uhttpd 进程崩溃。

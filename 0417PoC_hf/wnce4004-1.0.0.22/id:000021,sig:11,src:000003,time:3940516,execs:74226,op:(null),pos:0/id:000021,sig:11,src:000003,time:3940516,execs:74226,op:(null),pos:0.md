漏洞名称：
Netgear WNCE4004 USB_advanced 处理流程中的空指针解引用漏洞

Netgear WNCE4004 1.0.0.22 是 Netgear 公司旗下的一款无线网桥固件，受影响产品为 WNCE4004，受影响版本为 1.0.0.22。

Netgear WNCE4004 1.0.0.22 的 /usr/sbin/uhttpd 二进制文件中存在一个空指针解引用漏洞。远程攻击者可以构造特定的 POST 请求，通过 submit_flag 命中 USB_advanced 处理分支，并省略 hidden_is_ftp 参数，使程序在后续逻辑中直接读取空指针，最终导致进程崩溃。

该漏洞位于二进制文件 /usr/sbin/uhttpd 中。程序会先根据请求路径进入 apply.cgi 的 CGI 处理流程，再读取 submit_flag 选择具体的对象处理函数。本样本请求体中包含 submit_flag=USB_advanced，但没有 hidden_is_ftp 字段。程序在 0x408cc4 处调用 cgi_value("hidden_is_ftp") 返回 NULL，随后在 0x408cd0 处执行 lb v1, 0(v0) 直接解引用该空指针，最终触发 SIGSEGV。

攻击者可以远程发起攻击，通过发送缺少 hidden_is_ftp 字段的恶意 POST 请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前分析基于 greenhouse 仿真环境中的 WNCE4004 1.0.0.22 固件镜像完成。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。当前样本目录中的请求报文、trace 和日志已能对应到 cgi_setobject 分发以及 hidden_is_ftp 缺失后的空指针解引用崩溃点。

目标配置情况：

未进行特殊配置，使用默认仿真环境启动即可复现。

具体验证过程：

第一步。攻击者发送 POST 请求进入 /apply.cgi 路径，请求体中包含 submit_flag=USB_advanced，但不提供 hidden_is_ftp 参数。

第二步。uhttpd 在 cgi_setobject 中读取 submit_flag，并根据其值选择 USB_advanced 对应的处理函数。进入该函数后，程序继续尝试从 CGI 参数表中读取 hidden_is_ftp。
![alt text](image.png)

第三步。由于当前请求中缺少 hidden_is_ftp，cgi_value 返回 NULL。程序没有进行判空，而是在 0x408cd0 处直接读取该指针指向的首字节，最终触发空指针解引用并导致 uhttpd 进程崩溃。

漏洞名称：
Netgear WNDRMAC 1.0.0.10 0x40aa78 NULL 指针解引用漏洞

Netgear WNDRMAC 1.0.0.10 是 Netgear 公司旗下的一款网络设备固件，受影响产品为 WNDRMAC，受影响版本为 1.0.0.10。

Netgear WNDRMAC 1.0.0.10 的 `/usr/sbin/uhttpd` 二进制文件中存在一个 `NULL 指针解引用` 漏洞。远程攻击者可以通过发送构造的 HTTP 请求触发该问题。submit_flag 被读入后未命中任何 obj.funcs 动作项，导致全局 obj.cgi_action 保持全零，cgi_setobject 跳过唯一一次 obj.refresh_time 初始化，随后 do_apply 解引用了仍为 NULL 的 *obj.refresh_time。

该漏洞位于二进制文件 `/usr/sbin/uhttpd` 中。程序在 `/usr/sbin/uhttpd sym.cgi_setobject 0x40f7a4` 处对攻击者可控输入完成读取、解析或传递，并最终在 `/usr/sbin/uhttpd sym.do_apply 0x40aa78` 处进入危险操作，最终导致安全风险。

攻击者可以远程发起攻击，通过向目标设备发送恶意请求触发漏洞。

漏洞研究环境：

通过模拟仿真进行验证。当前样本目录中提供了对应的请求包与发送脚本 send.py，可用于复现该问题。

通过 greenhouse 进行仿真，greenhouse 链接为 https://github.com/sefcom/greenhouse。仿真环境搭建的具体命令链接为 https://github.com/sefcom/greenhouse/blob/master/MANUAL.md。
我在附件里面附上了 rehost 的镜像，链接为 https://github.com/GinRawin/PoC/blob/main/0417PoC_hf/wndrmac-1.0.0.10/wndrmac-1.0.0.10.tar.gz，启动的命令为进入到 dockerfile 目录下，然后 `docker-compose build`, `docker-compose up`。

目标配置情况：

没有进行特殊配置，默认仿真环境启动。

具体验证过程：

第一步。POST /apply.cgi 进入 post_apply，cgi_setobject 在 0x40f7a4 读取 body.submit_flag。

第二步。cgi_setobject 先清零 obj.cgi_action，随后在 0x40f830..0x40f848 用 submit_flag 遍历比较动作表；trace 只出现循环块，未出现命中块 0x40f7ec，因此 obj.cgi_action 保持全零。

第三步。handle_request 早先已把 *obj.refresh_time 清零；本次 cgi_setobject 又在 0x40f9c8 直接跳到 0x40f9e4，跳过 0x40f9d8 唯一写入点。

第四步。handle_request 最终调用 do_apply；do_apply 在 0x40aa78 对 *obj.refresh_time 做解引用，触发 SIGSEGV si_addr=NULL。
